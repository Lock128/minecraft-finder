# Vendored Cubiomes + FFI shim

This directory vendors a minimal, self-contained subset of
[Cubiomes](https://github.com/Cubitect/cubiomes) (MIT licensed) together with a
thin C shim (`mc_finder_ffi.c` / `mc_finder_ffi.h`) that exposes a flat, stable
C API for `dart:ffi`:

- `mcf_find_structures`
- `mcf_find_ores`
- `mcf_get_biome`

The shim returns plain structs/arrays so the Dart bindings generated by
`package:ffigen` stay simple, and so the native and web (pure-Dart) backends can
be held in lock-step against the shared golden-seed fixtures.

## Layout

- `cubiomes_core.h` / `cubiomes_core.c` — the vendored subset: the
  `java.util.Random` 48-bit LCG, the region-grid structure placement used by
  Minecraft Java 1.18-1.20, and a deterministic placeholder biome/ore sampler.
  This is a reduced port adequate for the structure placement the shim exposes;
  the upstream project carries the full biome generator, which can be dropped in
  wholesale (same file names) when expanding coverage.
- `mc_finder_ffi.c` / `mc_finder_ffi.h` — the flat FFI shim.
- `CMakeLists.txt` — builds `mc_finder_ffi` as a shared library (`.so`/`.dll`/
  `.dylib`) and a static library (`.a`) for all target platforms.

## Why a reduced vendored core

The build environment for this change is Linux-x64 only (no iOS/Android/macOS/
Windows SDKs or cross-compilers), so a full cross-platform Cubiomes compile and
a live on-device `NativeFfiBackend` run cannot be exercised here. The pipeline
(sources, shim, CMake, Gradle/Xcode wiring, ffigen config/bindings, backend with
load-failure handling) is implemented in full regardless; correctness of the
placement math is proven by asserting the pure-Dart web backend against the same
golden fixtures the native path targets.
